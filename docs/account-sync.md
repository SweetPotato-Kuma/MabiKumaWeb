# 계정과 개인 데이터 저장

비로그인은 기존 localStorage 키에 계속 저장한다. 서버에 익명 계정이나 백업을 만들지 않는다.
로그인한 사용자는 Google 인증 → 미등록 계정의 프로필 등록 → 계정 데이터 자동 동기화 순서로 이용한다.
외부 인증에는 Google Identity Services를 쓰며 다른 제공자는 아직 구현하지 않았다.
홈 화면 구성은 아직 만들지 않았다. 이후 개인 데이터 스키마에 항목을 추가하면 같은 저장 흐름을 쓸 수 있다.

## 운영 설정

OAuth 설정과 계정 전용 D1이 모두 준비되었을 때 `/account/config`가 활성 상태를 반환한다.
기존 조회·계산·로컬 저장은 이 설정 없이도 동작한다.

2026-10-10 운영 준비 상태: 계정 전용 D1 `mabikuma-accounts`를 생성하고 `0001_accounts.sql`을 적용했다.
Worker에는 `ACCOUNTS` 바인딩과 자체 도메인 `https://mabi-api.spkuma.com`을 연결했다.
GitHub Actions Variable `VITE_ACCOUNT_API_URL`도 이 주소로 설정했다.
Google OAuth 웹 클라이언트 ID는 `733364928830-env2pp751gvusr6e28vg1uafji6rafb6.apps.googleusercontent.com`이며
`worker/wrangler.toml`의 `GOOGLE_CLIENT_ID`에 설정한다. 이 ID는 공개 식별자이고 비밀 키가 아니다.
운영에서 활성화 여부는 허용된 사이트 Origin으로 `/account/config`를 요청해 `enabled: true`인지 확인한다.
다른 에이전트의 작업 방침은 `AGENTS.md`에 기록하며 `AGENT.md`에서도 이를 안내한다.

1. Google Cloud Console에서 OAuth 동의 화면과 **웹 애플리케이션 클라이언트**를 설정한다.
   승인된 JavaScript 출처에 `https://mabi.spkuma.com`을 추가한다. 개발 환경은 실제 사용하는 localhost 출처를 추가한다.
   팝업 버튼의 ID 토큰을 검증하는 방식이므로 클라이언트 비밀 키는 필요 없다.
2. `worker/wrangler.toml`의 `GOOGLE_CLIENT_ID`에 실제 클라이언트 ID를 설정한다. 이 값은 공개 식별자이며 비밀 키가 아니다.
   파일에 설정해야 이후 Worker 재배포에서도 값이 유지된다.
3. 계정 전용 D1은 현재 생성·바인딩되어 있다. 새 Cloudflare 계정으로 이전할 때만
   Worker 디렉터리에서 `npx wrangler d1 create mabikuma-accounts`를 실행하고 반환된 ID로 `ACCOUNTS` 바인딩을 바꾼다.
   Cloudflare 인증 오류가 나오면 먼저 `npx wrangler login`으로 CLI 인증을 다시 연결한다.
4. `npx wrangler d1 migrations apply mabikuma-accounts --remote`로 `migrations-accounts`의 스키마를 적용한다.
5. 인증 쿠키를 쓸 API는 `mabi-api.spkuma.com` 자체 도메인에 연결되어 있다.
   `*.workers.dev`와 프런트는 다른 사이트다. 현재 `SameSite=Lax` 쿠키는 이 교차 사이트 구성에서 전송되지 않으므로,
   쿠키 정책을 느슨하게 바꾸는 대신 자체 도메인을 사용한다.
6. `ALLOWED_ORIGINS`에 실제 프런트 출처를 명시하고 `npx wrangler deploy`한다.
7. 프런트 빌드 변수 `VITE_ACCOUNT_API_URL`을 그 자체 도메인으로 설정한다. 비우면 `VITE_PROXY_URL`을 사용한다.
   GitHub Pages 배포에서는 저장소의 Actions Variable로 설정한다. OAuth ID는 프런트 빌드에 넣지 않아도 된다.

로컬 Vite 개발은 `/account-api` 프록시를 사용할 수 있다. `.env`에 `VITE_ACCOUNT_API_URL=/account-api`와
`ACCOUNT_PROXY_TARGET=https://mabi-api.spkuma.com`을 넣는다. 해당 localhost 출처를 Google와 Worker 양쪽에 등록한다.
브라우저의 로컬 보안 쿠키 지원 여부도 확인한다. 개발 서버는 localhost로 접근한다.
운영 설정을 바꿀 때 기존 다른 데이터용 Worker 바인딩과 시크릿을 보존한다.

## 저장 대상과 분리

헤더는 비로그인일 때 `로그인`, 외부 인증 후 등록 전에는 `프로필 등록`, 등록 후에는 닉네임을 표시한다.
닉네임을 누르면 사용자 프로필에서 닉네임을 수정하고 연결된 로그인 제공자와 마지막 동기화 시점을 볼 수 있다.
동기화 시점은 이 브라우저가 서버 데이터를 성공적으로 확인하거나 저장한 때이며 실패한 요청으로는 갱신하지 않는다.
저장 상태, 버전 번호와 최근 복구본 메뉴는 화면에 표시하지 않는다. 내부 버전 검사는 동시 수정 방지를 위해 유지한다.
닉네임 변경은 인증된 본인 계정만 수정하며 기존 저장 내용이나 전송 대기열을 초기화하지 않는다.
로그인 창을 열면 Google 공식 버튼을 바로 불러온다. 별도의 준비 버튼, 파일 가져오기·내보내기와 수동 동기화 버튼은 두지 않는다.
로그인 후 재방문과 새로고침에서는 유효한 보안 쿠키로 세션과 계정 데이터를 자동 복원한다.
세션은 로그인한 시점부터 최대 30일이며, 만료 또는 명시적인 로그아웃 뒤에는 다시 인증해야 한다.

`shared/personal-data.js`가 서버와 프런트 공통 허용 목록이다.
재료 메모, 계산기의 `remember` 입력, 저장 검색, 가방 관심 조건, 던전 코인 보유 수량, 탈틴 농장 입력,
사용자 설정, 테마와 시뮬레이터 효과 설정을 동기화한다. 계산기의 모든 임시 입력이나 시뮬레이션 결과를 저장하지는 않는다.
API 키·관리자 키·시세와 아이템 캐시는 가져오지 않는다. 항목은 최대 100개, 전체 입력 데이터는 UTF-8 기준 256KiB다.

프로필은 닉네임만 받는다. Google 계정 고유 식별자와 내부 계정 UUID를 연결하고, 이름·이메일·사진은 보관하지 않는다.
외부 계정 하나에 내부 계정 하나를 연결한다. 여러 Google 계정을 같은 사람이라고 추정해 합치지는 않는다.
인증과 사용자 내용은 로그로 출력하지 않는다. Cloudflare 인프라의 요청 IP·운영 로그 처리는 개인정보 안내에 고지한다.
사용자 입력은 서버가 읽을 수 있는 형태로 D1에 저장한다. 종단간 암호화 백업은 아니다.

비로그인 데이터는 원래 키에 남는다. 로그인 데이터의 로컬 사본은 `mabikuma:account-data:<내부 UUID>`에
보관하며 로그인·로그아웃 시 메모리 캐시도 전환한다. 세션 토큰은 localStorage에 넣지 않고 HttpOnly·Secure 쿠키로 보관한다.
다른 탭에서 세션이 바뀌어도 이전 계정 내용을 새 계정에 보내지 않도록 API에서 요청한 계정과 세션의 계정을 비교한다.

## 자동 동기화와 충돌

프로필 등록 또는 기존 계정 연결 후 기존 로컬 입력을 클라이언트에서 자동으로 합친다.
처음 연결하는 브라우저에서는 계정에 없는 항목만 가져오며 같은 항목은 계정 값이 우선이다. 기존 비로그인 원본은 유지한다.
계정 사본의 `guestBase`에 마지막으로 확인한 비로그인 입력을 기록한다. 재로그인에서는 이후 바뀐 값만 반영하며,
미전송 계정 수정이 있는 항목은 그 수정을 우선한다. 다른 기기도 같은 항목을 수정했다면 충돌로 남긴다.
비로그인 원본에 항목이 없다는 이유로 서버 항목을 삭제하지 않는다. 로그인 후 항목 삭제는 일반 동기화로 반영한다.
값이나 수량을 자동 합산하지 않는다.

변경은 약 1초 모아서 전송한다. 활성 탭은 30초 간격과 다시 온라인·화면 복귀 시 원격 상태를 확인한다.
마지막 서버 확인본, 이 기기 입력, 원격 내용을 비교한다. 서로 다른 항목 변경은 반영하지만 같은 항목 변경은
덮어쓰지 않고 사용자 선택을 기다린다. 재료 메모 같은 한 항목 내부의 변경도 충돌로 취급한다.
서버는 SQL 조건부 갱신으로 이전 버전의 쓰기를 거부한다. 저장 도중 입력한 값은 다음 전송 대상으로 남긴다.
서버 확인이 끝나야 마지막 동기화 시점을 갱신한다. 실패·만료 시 기기 사본을 유지한다.

복구본은 SQLite 트리거로 현재 저장과 함께 기록하며 최근 5개만 내부에 보관한다. 사용자 화면에 복원 메뉴를 두지 않는다.
기기 사본과 아직 서버에 전송되지 않은 변경까지 항상 복구되는 것은 아니다.
브라우저 초기화 후에는 로그인으로 서버 저장 내용을 받아오며 빈 초기값을 서버에 자동 업로드하지 않는다.

## 보관과 삭제

방문만으로 저장 행을 만들지 않는다. 인증했으나 프로필 등록을 마치지 않은 임시 계정은 7일 뒤 정리한다.
인증 nonce는 5분, 세션은 최대 30일이며, 계정당 최근 세션 10개만 남긴다. 기존 10분 크론에서 만료 데이터를 정리한다.
등록한 정상 계정과 데이터는 미접속만으로 삭제하지 않는다.
계정 삭제는 운영 DB의 계정·세션·현재 내용·복구본을 외래 키 연쇄 삭제로 제거한다. 현재 브라우저의 계정 사본도 제거한다.
다른 기기 사본은 사용자가 따로 지워야 한다. Cloudflare의 인프라 백업 보관 기간은 요금제 정책을 따른다.

## 배포 후 확인

- 비로그인 수정·새로고침, 최초 외부 인증·동의 없는 등록 차단·동의 후 등록.
- 로컬 입력 자동 합치기, 계정 값 우선, 반복 로그인 시 오래된 값의 재업로드가 없는지.
- 새 브라우저의 복원, 로그아웃 후 원래 비로그인 데이터, 계정 전환·다른 탭 로그인.
- 서로 다른 항목 수정과 동일 항목 충돌, 오프라인 입력 후 재연결, 인증 만료·재로그인.
- 공식 로그인 버튼 하나, 파일 메뉴·수동 동기화 버튼 없음, 재방문 시 자동 로그인 복원.
- 닉네임 수정과 미전송 입력 보존, 동기화 시점, 계정 삭제와 다른 계정 영향 없음.
- 인증 실패·출처 불일치·허용 목록 밖 데이터·과도한 용량·오래된 버전 쓰기 차단.
