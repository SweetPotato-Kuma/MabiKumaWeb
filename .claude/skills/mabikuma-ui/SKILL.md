# MabiKuma UI 스킬

출처: [Taste Skill v2](https://www.tasteskill.dev/) (Leonxlnx/taste-skill, MIT)의 안티슬롭 정책을
이 프로젝트의 브리프(게임 데이터 조회 도구 + antd)에 맞게 각색하고 고정한 것이다.
원문은 랜딩 페이지·포트폴리오 전용이고 대시보드·데이터 테이블은 명시적으로 범위 밖(§13)이므로,
**구현 레이어는 antd로 치환하고, 히어로·벤토·마퀴 등 랜딩 전용 규칙은 §8에서 명시적으로 해제**했다.

---

## 0. 디자인 리드 (고정)

이 프로젝트의 브리프는 매번 추론하지 않는다. 아래가 확정값이다.

- **성격**: 마비노기 오픈 API 기반 경매장 시세 조회 도구. 마케팅 사이트가 아니라 **조회 도구**다.
- **사용자**: 게임 중 시세를 빠르게 확인하려는 한국어 사용자. 모바일 비중이 높다.
- **요구**: 검색 결과에 최단 시간 도달, 숫자 가독성, 지연 데이터(약 10분)에 대한 정직한 고지.
- **제약**: 개인이 만든 비공식 도구. 넥슨 브랜드를 흉내 내지 않는다. 공식인 척하는 배지나 문구 금지.
- **톤**: 조용하고 기능적. "차세대", "혁신적", "Seamless" 류 마케팅 동사 금지.

## 1. 다이얼 (고정)

- `DESIGN_VARIANCE: 4` - 예측 가능한 그리드 우선. 비대칭 레이아웃은 조회 도구에서 비용만 된다.
- `MOTION_INTENSITY: 3` - hover / active / focus 전이까지만. 스크롤 연출과 패럴랙스 없음.
  예외: 세공 시뮬레이터의 세공 창, 유물 복원 시뮬레이터의 복원 창, 무리아스의 성수 시뮬레이터의 성수 창은 사용자가
  재미를 위해 연출을 요청해 올렸다(2026-09). `src/components/reforge/reforgeFx.css`, `src/components/relics/relicFx.css`,
  `src/components/holyWater/holyWaterFx.css` 에만 있고, transform/opacity 만 움직이며, "세공 연출"/"복원 연출"/"성수 연출"
  끄기만 따른다. 움직임 줄이기 설정과는 무관하다(사용자 요청, 2026-10). 드문 결과(세공의 한계 돌파, 복원의 10레벨, 성수의 최대치 98% 이상)에는
  금빛(antd `gold` 토큰)이 번쩍인다. 성수는 최대치의 50/90/95/98% 이상마다 연출이 한 겹씩 더해지고, 98% 이상(최대 대미지 29, 30 같은 최상위)은
  사용자 요청으로 연출 밖에서도 금색 팔레트(글자 gold7/gold8, 바탕 gold1)로 칸과 태그를 칠한다. 시뮬레이터 밖으로 번지게 하지 않는다.
  주화 시뮬레이터의 만들기 창도 같은 이유로 연출이 있다(2026-10, `src/components/coins/coinFx.css`, "주화 연출" 끄기).
  점수가 토템 만점의 50/75/90/95% 이상마다 한 겹씩 더해지고, 95% 이상은 금빛과 금색 팔레트다.
  오검 워드 시뮬레이터는 연출 없이, 최대 레벨의 90% 이상인 옵션 줄만 금색 팔레트(바탕 gold1, 글자 gold8, 별)로 칠한다(2026-10).
  에코스톤 각성 시뮬레이터는 사용자 요청으로 연출이 있다(2026-10, `src/components/echostone/echostoneFx.css`, "에코스톤 연출" 끄기).
  각성하면 빛 구슬이 돌로 모여 터지며 능력 카드가 나오고, 레벨이 최대 레벨의 50/75/90% 이상마다 번쩍임, 빛살, 금빛이 한 겹씩
  더해진다. 각성제마다 빛 구슬이 다르다(일반 셋 곧게, 고급 다섯 돌며, 최고급 여덟 금빛과 금빛 고리). 연마석 레벨 재부여는
  돌 없이 카드 위를 빛 줄기가 훑고 이전 레벨이 새 레벨로 뒤집힌다. 목표까지 자동으로 돌릴 때는 연출이 없다. 90% 이상은 연출
  밖에서도 금색 팔레트로 칠한다.
  키트 시뮬레이터는 사용자 요청으로 연출이 있다(2026-10, `src/components/kits/kitFx.css`, "키트 연출" 끄기). 한 번 열면 상자가
  터지며 아이템 카드가 나오고, 셋째·둘째·첫째 등급마다 번쩍임, 빛살, 반짝임과 금빛이 한 겹씩 더해진다. 여러 번 열기는 연출 없이
  마지막 것을 판에 놓는다(지난 결과 줄은 아래 얻은 아이템 표와 겹쳐 두지 않는다, 사용자 요청). 첫 등급(S 등급) 아이템은 연출 밖에서도 금색 팔레트로 칠한다. 등급이 없는 키트는 겹 없이 상자만 열린다.
- `VISUAL_DENSITY: 6` - 표준 앱 밀도. 결과 영역은 촘촘하게, 진입 영역은 숨 쉬게.

Taste Skill 기본값 8/6/4는 랜딩용이므로 적용하지 않는다. 사용자가 대화로 올리라고 하면 그때만 올린다.

`VISUAL_DENSITY 6`의 귀결: **숫자는 전부 `font-variant-numeric: tabular-nums`**. 가격·수량·시간 컬럼은 우측 정렬.

## 2. 디자인 시스템: antd 하나

**One system per project.** antd 외 UI 라이브러리를 이 트리에 섞지 않는다.
Tailwind, shadcn/ui, MUI, Chakra, Bootstrap 전부 금지. 새 UI 의존성은 사용자 승인 없이 추가하지 않는다.

- 컴포넌트: `antd`
- 아이콘: 구글 **Material Symbols Rounded(굵기 400) 단일 패밀리**. `src/components/icons.tsx`에서만 가져온다.
  새 아이콘은 `@material-symbols/svg-400/rounded/<이름>.svg?raw`를 그 파일에 한 줄 더해 쓴다.
  SVG 아이콘을 손으로 그리지 않는다. 이모지로 아이콘을 대체하지 않는다. `@ant-design/icons`를 직접 import 하지 않는다
  (antd 내부의 닫기, 화살표 같은 글리프는 antd 몫이라 그대로 둔다). 돌아가는 로딩 표시는 아이콘 대신 antd `Spin`.
- 애니메이션 라이브러리 추가 금지. antd 내장 모션으로 충분하다 (`MOTION_INTENSITY 3`).

### 2.A 의존성 검증 (필수)

import 전에 `package.json`을 확인한다. 없으면 **먼저 설치 명령을 제시**한다. 존재를 가정하지 않는다.

```bash
npm i antd @material-symbols/svg-400
```

### 2.B antd를 쓴다는 것의 의미

- antd가 제공하는 컴포넌트를 CSS로 재구현하지 않는다. `Table`, `Form`, `Select`, `Empty`, `Skeleton`, `Result`, `Alert`, `Tag`, `Statistic`, `Descriptions`, `Segmented`, `Tabs`, `Drawer`를 먼저 찾는다.
- 반대로 antd 기본 상태 그대로 내보내지도 않는다. 토큰(§3)으로 프로젝트 정체성을 입힌다.
- 컴포넌트에 색을 인라인으로 하드코딩하지 않는다. 색은 전부 토큰에서 나온다.
- `!important`로 antd 내부 클래스(`.ant-*`)를 덮어쓰지 않는다. `ConfigProvider`의 `theme.components`로 조정한다.

## 3. 토큰 (단일 출처)

색·반경·폰트는 **`ConfigProvider` 테마 한 곳**에서만 정의한다. 컴포넌트마다 다른 값을 쓰지 않는다.

```tsx
<ConfigProvider theme={{ algorithm: isDark ? theme.darkAlgorithm : theme.defaultAlgorithm, token: {...} }}>
```

### 3.A 색: Color Consistency Lock

- **색은 로고에서 온다.** 액센트는 1개, 고구마 껍질 보라 `#9e3563`(다크 `#e48db3`)다. 회색은 전부 갈색 쪽으로 데운 것을 쓴다
  (라이트 바탕 크림 `#f7f2ee`, 다크 바탕 초콜릿 `#17120f`, 글자 `#2e201b`/`#f1e7e0`). 파란 기가 도는 회색을 새로 들이지 않는다.
- 액센트 위 글자는 흰색이 아니라 `ON_ACCENT`(라이트는 카드 바탕, 다크는 어두운 바탕)다. 밝은 다크 액센트에 흰 글자는 대비가 무너진다.
- 보라는 링크, 주 버튼, 선택 상태, "고른 것/1위" 표시에만 쓴다. 일반 가격과 수치는 본문색에 굵기로만 강조한다.
- 페이지마다, 섹션마다 다른 액센트를 쓰지 않는다. 7번째 화면에서 갑자기 청록 배지가 나오면 실패다.
- 의미 색은 액센트와 별개다. success / warning / error는 antd 시맨틱 토큰으로만 쓰고 장식으로 쓰지 않는다.
- 데이터 색도 액센트와 별개다. 한 막대나 차트를 여러 항목으로 나눠 "어느 항목인가" 를 가를 때는 `theme.ts`의
  `SERIES_COLORS`를 앞에서부터 순서대로 쓴다(돌려 쓰지 않는다). 순서가 색각 이상 구분을 지키므로 색이나 순서를 바꾸면
  다시 검증하고, 색만으로 가르지 않게 번호나 이름, 표를 함께 둔다. 한 가지 값의 진하기를 나타낼 때는 쓰지 않는다.
- **순수 `#000` / `#fff` 금지.** off-black / off-white를 쓴다.
- 네온 글로우, 외곽 발광, 보라 그라데이션(AI 퍼플) 금지. 그림자는 배경 색조에 맞춰 tint한다.
- 그라데이션 텍스트로 제목을 칠하지 않는다.

### 3.B 형태: Shape Consistency Lock

반경 스케일은 하나다. `borderRadius: 10`을 기준으로 antd가 파생시키는 값을 그대로 쓴다.
네모난 카드 위에 알약 버튼을 얹는 식의 혼합은 금지. 규칙을 바꾸려면 토큰에서 바꾼다.

### 3.C 타이포

- **글꼴은 Pretendard 하나.** npm `pretendard`의 dynamic subset CSS를 `main.tsx`에서 싣고(self-host, `font-display: swap`),
  `theme.ts`의 `FONT_FAMILY`가 antd 토큰과 `--app-font`로 함께 내보낸다. 다른 글꼴을 섞지 않는다.
- 세리프 금지. 이 브리프는 편집이나 럭셔리가 아니다.
- `<link>`로 Google Fonts나 외부 CDN 글꼴을 붙이지 않는다.
- 크기는 다섯 단계만: 페이지 제목 24(antd `Title level={3}`), 카드·섹션 제목 16, 본문 15, 보조 13, 주석 12.
- 글자색은 세 단계만: 본문(`colorText`), 보조(`colorTextSecondary`, `type="secondary"`), 비활성(`colorTextTertiary`). 새 회색을 만들지 않는다.
- Pretendard 숫자는 넓다. 큰 숫자는 `whiteSpace: 'nowrap'`으로 쪼개지 않고, 칸이 좁으면 칸째 다음 줄로 넘긴다.
- 제목은 크기가 아니라 **굵기와 색으로 위계**를 만든다. 조회 도구에 화면을 뒤덮는 거대 제목은 없다.
- 본문 가독 폭은 65ch 내외. 테이블과 폼은 예외.

### 3.D 다크모드 (필수)

- 라이트와 다크 **양쪽을 동시에 설계**한다. 한쪽만 보고 끝내지 않는다.
- 기본은 `prefers-color-scheme` 추종. 수동 토글을 붙이려면 설정 페이지에 둔다.
- **Page Theme Lock**: 한 화면은 하나의 테마다. 다크 화면 중간에 밝은 섹션이 끼어들지 않는다.
- 위계 패리티: 라이트에서 눈에 띄던 주 버튼은 다크에서도 똑같이 눈에 띄어야 한다.
- 대비: 본문 WCAG AA(4.5:1), 큰 텍스트 3:1 이상. 양쪽 모드 모두에서 검증한다.
- 경계 대비(카드 바탕 기준, `theme.ts`의 SURFACE 주석이 원본): 입력칸과 기본 버튼 테두리(`colorBorder`) 1.7~1.9:1,
  카드와 표의 선(`colorBorderSecondary`) 1.3:1 안팎(더 올리면 선이 화면을 가둔다), 카드와 페이지 바탕 1.13:1. 다크에서 경계가 사라지면 이 값부터 본다.
- 흐린 글자 단계도 직접 잡는다. antd 기본(본문색에 투명도 0.45)은 4.5:1에 못 미친다. 보조 안내문(`type="secondary"`)과
  placeholder는 4.5:1 이상, 비활성만 3:1 안팎.
- CSS 변수와 antd 토큰이 **둘 다 진실을 주장하지 않게** 한다. 한쪽이 원본이고 다른 쪽이 파생이다.

## 4. 상태와 폼

LLM은 "성공한 정적 상태"만 만든다. 이 프로젝트에서는 **네 가지 상태를 전부** 구현한다.

- **로딩**: 최종 레이아웃 모양을 닮은 `Skeleton`. 범용 스피너를 기본값으로 쓰지 않는다.
- **빈 상태**: `src/components/EmptyState`(곰 그림을 끼운 antd `Empty`) + 무엇을 하면 채워지는지 한 줄. "결과 없음"만 던지지 않는다.
  `Empty`를 직접 쓰지 않는다. 모달이나 패널 안에서는 `size="small"`. 찾기 전 안내("~를 고르면 나옵니다")는 `variant="search"`. 표와 목록의 빈 칸은 `AppProviders`의 `renderEmpty`가 맡는다.
- **에러**: 폼 안이면 인라인, 조회 실패면 `Alert`나 `Result`. 토스트는 일시적 피드백에만.
- **성공/결과**: 여기가 본론이다. 데이터 신선도(약 10분 지연)를 결과 근처에 명시한다.

기존 `QueryState` 컴포넌트가 이 계약을 담당한다. 새 조회 화면은 이걸 통과시킨다.

### 4.A 폼 규칙

- `Form layout="vertical"`. **라벨은 입력 위**, 에러는 입력 아래.
- **placeholder를 라벨로 쓰지 않는다. 예외 없음.** placeholder는 예시값 전용이다.
- placeholder, helper, 에러, 포커스 링 전부 배경 대비 AA를 통과해야 한다.
- 제출 버튼 라벨은 한 줄에 들어간다. 데스크톱에서 두 줄로 접히면 실패다.
- 버튼 텍스트와 버튼 배경의 대비를 매번 확인한다. 흰 배경 위 흰 글씨류는 즉시 실패.
- 체크박스와 라디오는 **상자와 글자까지만** 눌려야 한다. 세로 `Flex`나 블록 안에 두면 줄 폭 전체로 늘어나
  빈 곳을 눌러도 켜진다. 세로로 쌓을 때는 `<Flex vertical align="flex-start">`로 글자 폭만큼만 둔다.

### 4.B 데이터 표시

- 5행 이상 목록에 맨 `<ul>` + 행마다 hairline은 가장 게으른 선택이다. `Table`, `List`, `Descriptions`, 카드 그리드 중에서 고른다.
- 행마다 `border-top`과 `border-bottom`을 동시에 긋지 않는다. 하나만 고른다.
- 배경 트랙이 채워진 진행 막대를 비교 시각화로 쓰지 않는다. 숫자 + 작은 아이콘이 낫다.
- **가짜 정밀 숫자 금지.** 화면에 보이는 수치는 API 응답에서 오거나, 목업이라고 코드 주석에 표시되거나, 둘 중 하나다.
- 표본이 적은 통계는 "표본 N건"을 같이 보여준다. 신뢰도를 숨기지 않는다.
- 시뮬레이터(세공, 유물 복원처럼 매번 같은 확률로 따로 뽑는 것)에는 방문자가 **고른 특정 결과**
  (세공의 목표 옵션, 복원의 보고 싶은 유물)를 n 번 했을 때 볼 확률을 `src/components/simulator/TrialOdds`로
  붙인다. 한 번 이상 나올 확률(1 - (1 - p)^n)과 기댓값(n x p), 비용만 보여 준다. "50%/90%/99% 로 보려면 몇 번"
  같은 자세한 줄은 사용자가 원하지 않아 두지 않는다. 계산은 `src/features/simulator/trials.ts` 하나에서만 한다.
  카드에는 한 번 기준 숫자(본전 확률 등)만 두고, n 번 입력이 있는 계산은 모두 떠 있는 계산기 창(Popover, 창 밖을
  눌러도 닫히지 않게, "특정 유물 기댓값" "특정 세공 기댓값")에 모아 카드를 길게 만들지 않는다. 창 맨 위에
  `TrialCountInput`("시행 횟수") 하나를 두고 창 안의 계산이 모두 그 횟수를 쓴다(`TrialOdds`에 `trials`를 넘긴다).
  본전 n 번은 "n 개 결과의 시세 합이 n 번 든 값 이상일 확률" 이다(`src/features/simulator/breakEven.ts`).
  카드 안에서 다른 줄과 이어 쓸 때는 `framed={false}`로 상자를 뺀다. 상자가 카드를 둘로 갈라 보이게 한다.

### 4.C 아이템 사전의 이름은 상세로 가는 길

- 아이템 정보 화면 안에서 **다른 아이템의 이름**을 보여 주면(제작 재료 트리의 재료와 하위 재료, 요리 비율 표의 재료 등)
  그 이름을 `src/components/ItemInfoLink`로 그려 그 아이템의 상세에 닿게 한다. 새로 만드는 목록과 표도 같다.
- 펼쳐 보기나 표 안에서 바로 보이는 정보는 그대로 둔다. 링크는 **더하는 것**이지 펼침을 대신하지 않는다.
- 줄 전체를 누르는 영역으로 만들지 않는다. 줄 안의 구하는 방법 선택이나 펼침 단추와 부딪힌다. 이름만 링크다.
- 사전에 카테고리가 없는 아이템(경매장에 오른 적 없는 재료)도 이름만으로 상세가 열린다. 링크를 빼지 않는다.
- 새 탭으로 열 수 있게 진짜 `<a href>`(react-router `Link`)를 쓴다. `onClick`으로만 이동하지 않는다.

## 5. 레이아웃

- 페이지 컨테이너 최대 폭을 고정하고 가운데 정렬한다. 초광폭 모니터에서 텍스트가 화면 끝까지 늘어지지 않게.
- **내비게이션은 데스크톱에서 한 줄.** 높이 64~72px, 최대 80px. 안 들어가면 라벨을 줄이거나 메뉴로 접는다.
- 다단 레이아웃은 **CSS Grid**로. `calc(33% - 1rem)` 류의 flex 산수 금지.
- 전체 높이가 필요하면 `100dvh`. `100vh`는 모바일 사파리에서 튄다.
- 모든 다단 레이아웃은 `< 768px`에서의 1단 폴백을 **같은 파일에 명시**한다. "알아서 되겠지" 금지.
- z-index를 남발하지 않는다. sticky 헤더, 드로어, 모달, 토스트 정도의 체계적 레이어에만 쓰고 상수로 관리한다.

## 6. 금지 패턴 (AI Tells)

### 6.A 절대 금지

- **em-dash(`—`)와 구분자용 en-dash(`–`)는 화면에 보이는 모든 문자열에서 0개.** 제목, 라벨, 버튼, 본문, 캡션, alt, 에러 메시지 전부. 일반 하이픈 `-`이나 쉼표, 괄호, 문장 분리로 대체한다.
- **가운데점 `·`은 한 줄에 최대 1개.** 기본 구분자로 남용하지 않는다. 줄바꿈이나 열 분리를 먼저 고려한다.
- 의미 없는 색 점(status dot)을 내비, 목록, 배지 앞에 붙이지 않는다. 실제 상태를 나타낼 때만, 화면당 최소한으로.
- 섹션 번호 eyebrow(`01 / 개요`, `002 기능`) 금지.
- 작은 대문자 eyebrow 라벨을 모든 섹션 제목 위에 붙이지 않는다. 화면당 1개면 충분하고, 없어도 된다.
- `v0.1.0`, `Build 0048`, `last sync 4s ago` 같은 버전이나 빌드 문자열을 장식으로 노출하지 않는다.
- 스크롤 유도 문구(`Scroll`, `아래로 스크롤`) 금지.
- 커스텀 마우스 커서 금지.
- `<div>`로 가짜 스크린샷이나 가짜 UI를 만들지 않는다.

### 6.B 콘텐츠

- 목업 데이터에 "홍길동", "Acme", `99.99%`, `1234567` 류를 쓰지 않는다. 마비노기 맥락에 맞는 실제 같은 값을 쓴다.
- 문구는 기능적으로. 시적인 라벨("장인의 기록", "현장의 메모") 금지.
- 출고 전 **화면에 보이는 모든 문자열을 다시 읽는다.** 문법이 깨졌거나, 지시 대상이 불분명하거나, 귀엽기만 하고 뜻이 없는 문장은 평범한 기능 문장으로 바꾼다.
- **설명 문장을 늘어놓지 않는다**(사용자 요청, 2026-09). 페이지 부제, "~를 누르면 ~합니다" 류 안내, 표 아래 각주를
  쓰지 않고 숫자와 라벨, 조작 요소만 둔다. 제목 옆 ⓘ 설명 그림(InfoIcon + Tooltip)도 두지 않는다(사용자 요청,
  2026-09). 설명을 숨겨 두는 자리로도 쓰지 않는다.
  예외는 사용자가 자리를 지정한 것 하나다. 장비 개조 칸 이름 옆 (?) 에 올리면 개조 NPC 이름이 작은 글자로 보인다(2026-09).
  같은 정보를 줄과 고르는 칸에 되풀이하지 않고 이 한 곳에만 둔다.
  게임 데이터 10분 지연과 비공식 도구 고지는 예외로 남기되 짧게 쓴다. 빈 상태 문구도 한 줄로 짧게.

### 6.C 이모지

기본 금지. 아이콘은 `src/components/icons.tsx`(Material Symbols)에서 가져온다.
예외 없음. 브랜드 마크는 이모지가 아니라 그림이다. 헤더는 `src/assets/logo-mark.png`와 로고 글자
`wordmark.png`(다크 모드는 밝게 칠한 `wordmark-dark.png`), 공유 미리보기는 `public/og-image.png`,
파비콘은 `public/favicon.png`, `favicon.ico`, `apple-touch-icon.png`를 쓴다. 로고를 바꾸면 넷을 함께 바꾼다.

## 7. 접근성과 성능

- `prefers-reduced-motion: reduce`에서 전이와 반복 애니메이션을 끈다. antd 는 `theme.ts`의 `motion` 토큰으로 끈다.
  CSS 로 모든 요소의 `transition-duration`을 줄이지 않는다. 전환이 없던 `top`/`left`에도 전환이 생겨 팝업이 자리를 잘못 재고 화면 밖으로 튄다.
- 애니메이션은 `transform`과 `opacity`만. `width`, `height`, `top`, `left`를 애니메이트하지 않는다.
- `window.addEventListener('scroll')` 금지. 필요하면 `IntersectionObserver`나 CSS scroll-driven animation.
- `useEffect` 안의 타이머, 리스너, 애니메이션은 cleanup을 반드시 반환한다.
- 이미지, 차트, 임베드는 자리를 미리 확보해 CLS를 막는다.
- 키보드만으로 검색에서 결과, 상세까지 도달 가능해야 한다. 포커스 링을 지우지 않는다.
- 한국어 화면이므로 `lang="ko"`를 유지하고 `aria-label`도 한국어로 쓴다.

## 8. 이 프로젝트에서 해제된 Taste Skill 규칙

원문이 랜딩과 포트폴리오 전용으로 규정한 아래 항목은 **적용하지 않는다**. 억지로 끼워 넣지 말 것.

## 10. 현재 구조

- **토큰의 원본은 `src/app/theme.ts` 하나다.** 색·반경·폰트를 바꾸려면 여기만 고친다.
  `buildThemeConfig(mode)`가 antd `ConfigProvider` 설정을, `applyThemeVariables(mode)`가
  body와 오버스크롤 영역이 쓰는 `--app-*` 커스텀 프로퍼티를 내보낸다. CSS는 파생이지 출처가 아니다.
- `src/app/AppProviders.tsx`가 유일한 `ConfigProvider`다. 개별 화면이 테마를 덮어쓰지 않는다.
- 테마 선택(시스템/라이트/다크)은 `src/lib/themePreference.ts`가 들고 있고 설정 화면에서 바꾼다.
  저장소 접근 방식은 `src/lib/settings.ts`의 `useSyncExternalStore` 패턴을 그대로 따른다.
- `src/styles/index.css`는 antd 바깥만 담당한다. 리셋, body 배경, `.tnum`, reduced-motion.
  여기에 컴포넌트 스타일이나 색 상수를 새로 만들지 않는다.
- 숫자 칸에는 `className="tnum"`을 붙인다. Table 컬럼은 `align: 'right'`와 함께 쓴다.
- antd 는 번들의 대부분(gzip 약 348 KB)이다. `vite.config.ts`의 `manualChunks`가 antd 와 react 를
  앱 코드에서 떼어 놓는다. 화면 한 줄 고칠 때 방문자가 라이브러리를 다시 받지 않게 하려는 것이니
  이 분리를 되돌리지 않는다.
- **홈 화면(`src/pages/HomePage.tsx`)의 배치는 사용자 요청으로 정했다(2026-10).** 맨 위에 이벤트 배너(`BannerCarousel`, 공식 메인처럼
  큰 그림을 페이드로 자동으로 넘기고 좌우 화살표, 번호, 멈춤 단추를 둔다), 그 아래 왼쪽(1200px 이상)에 새소식 블록(`NewsBlock`,
  분류 탭과 8개 목록이라 스크롤 없이 한 화면), 오른쪽에 위젯 열(`KitWidget`, `DevNoteWidget`, `EditedWidget`), 맨 아래에 바로가기다.
  1200px 미만은 한 줄로 쌓는다. 위젯은 보일 것이 없으면(받는 동안, 오류, 글 없음) 자리를 만들지 않고 사라진다. 새 위젯을
  더할 때도 같다. 배너와 새소식은 워커가 모은 공식 홈페이지 기록(`worker/banners.js`, `news.js`)을 읽는다. 바로가기는 메뉴 표
  (`app/navigation.tsx`)를 그대로 읽는다. 루트를 다른 곳으로 넘기지 않는다. 넘기면 구글이 첫 화면을 수집하지 않아 검색 결과에
  사이트 이름과 아이콘이 뜨지 않는다.
- **자동으로 넘어가는 것에는 멈춤 단추를 둔다.** 배너처럼 5초가 넘게 움직이는 것은 사용자가 멈출 수 있어야 하고, 마우스를 올리거나
  초점이 가면 멈추며, OS 의 움직임 줄이기가 켜져 있으면 자동으로 넘기지 않는다. 큰 그림은 한꺼번에 받지 않고 지금 칸과 다음 칸만 받는다.
- **새소식(`/news`)의 본문은 공식 홈페이지 HTML 이다.** 그리기 전에 `src/features/news/sanitize.ts` 로 거른다(스크립트,
  on* 속성 제거, 무채색 글자색과 밝은 바탕 제거로 다크 모드에서도 읽히게). 본문 칸의 CSS 는 `src/components/news/newsBody.css`
  하나이고 색은 `--app-*` 에서만 온다. 글 한 편은 `/news?id=` 로 연다. 경로로 나누면 정적 호스팅이 글마다 404 를 낸다.
- **설정 화면은 없다.** 방문자가 키를 직접 넣을
  통로가 없으므로, 조회 불가 상태에서 "설정에서 키를 넣으라"고 안내하지 않는다.
  왜 안 되는지와 언제 풀리는지만 알린다. 고칠 수 있는 사람은 운영자다.
- 다크 모드 토글은 헤더에 있다. 설정 화면이 없어진 자리를 대신한다.
- 헤더 높이는 `theme.ts`의 `headerHeightFor(screens)` 하나에서 나온다(1200px 이상 72, 미만 56). 레이아웃, 메뉴,
  sticky 로 헤더 아래에 붙는 것(표 머리 `sticky.offsetHeader` 포함)이 같은 값을 읽는다.
- 경매장과 아이템 정보(카테고리별, 제작 스킬별)는 `src/components/BrowseLayout` 하나로 2단을 짠다. 왼쪽 칸 폭과 간격,
  제목 줄(보기 전환은 제목 오른쪽, 아래 줄에 두지 않는다)이 화면마다 달라지면 오갈 때 덜컹거린다. 따로 `Row`/`Col`을 짜지 않는다.
- 메뉴 구조(대분류, 소제목, 칸)의 원본은 `src/app/navigation.tsx` 하나다. 헤더 메뉴, 서랍, 전체 검색(Ctrl+K,
  `CommandPalette`)이 모두 이 표를 읽는다. 화면을 더하면 여기에 한 줄만 적는다. 대분류는 화면이 없고 펼치기만 한다.
- 가로 메뉴는 1200px 이상에서만 쓴다(`hasFullNav`). 그 아래는 헤더의 메뉴 단추가 여는 오른쪽 서랍이다.
  antd 넘침 메뉴(...)에 묶음 칸이 끼면 휴대폰에서 화면 밖으로 밀린다. 메뉴 칸을 늘리면 1200px 에서 한 줄에 드는지 본다.
  자리를 지키려고 가로 메뉴의 첫 줄 칸에는 아이콘을 두지 않고(펼친 목록, 서랍, 전체 검색에는 둔다), 검색 단추는 1600px
  미만에서 아이콘만 둔다(2026-10). 헤더 오른쪽에 무엇을 더하면 1200px 에서 넘침 메뉴가 생기지 않는지 브라우저로 잰다.

### 10.A 모바일 (휴대폰 폭)

- 가장 좁은 기준은 320px 이다. 360, 412(갤럭시 울트라 계열)에서도 가로 스크롤 없이 읽혀야 한다.
- 표는 768px 미만에서 칸을 합친다. 가장 중요한 값(대개 가격)만 제 칸에 두고 나머지는 이름 아래 보조 글자로 내린다.
  `scroll.x`로 가로로 밀게 두면 이름 칸이 한 글자 폭으로 눌린다. 가격 칸은 `whiteSpace: 'nowrap'`.
- 한 줄에 두 칸 이상 늘어놓는 격자는 `repeat(auto-fill, minmax(<한 칸 최소 폭>px, 1fr))`로 두어 좁으면 알아서 한 칸이 되게 한다.
- 다섯 칸 넘는 `Segmented`는 576px 미만에서 `Select`로 바꾼다. 잘린 끝 칸은 있는 줄도 모른다.
- `Popover`는 768px 미만에서 `placement="bottom"`을 쓴다. antd 는 `bottomLeft`/`bottomRight` 창을 좌우로 뒤집기만 하고
  화면 안으로 밀어 넣지 않아, 줄 가운데 단추의 창이 화면 밖으로 나갔다.
- 창 안에서 입력칸을 나란히 둘 때는 grid `minmax(0, 1fr)`이나 `minWidth: 0`을 준다. flex 기본값이면 자리 글 길이 밑으로
  줄지 못해 옆 칸이 창 밖으로 밀린다.
- 자동완성 목록 줄을 꾸밀 때는 `optionRender`를 쓴다. `label`에 넣으면 고른 뒤 입력칸 안에도 같은 모양으로 그려진다.
- 좁은 화면에서만 달라야 하는 antd 여백은 토큰으로 바꾼다(`buildThemeConfig`의 `narrow`, `useNarrowScreen`). `.ant-*`를 CSS 로 덮지 않는다.
- 한국어 줄바꿈은 `index.css`의 `word-break: keep-all`이 맡는다. 낱말 가운데서 끊기면 폭이 모자란 것이니 칸 구성을 고친다.
- 화면 문구에 "왼쪽에서", "오른쪽 칸" 처럼 데스크톱 배치를 가정한 방향어를 쓰지 않는다. 휴대폰에서는 위아래로 쌓인다.
